# ssosn — 強2階探索表記の順序数解析

Kanrokoti さんの「強2階探索表記」（strong second-order search sequence, SSOS）を順序数で解析しています。各列 S に順序数 o(S) を対応させて、小さい列から順に表を作るのが目的です。

- 定義: 巨大数研究 Wiki「ユーザーブログ:Kanrokoti/強2階探索表記」
  https://googology.fandom.com/ja/wiki/ユーザーブログ:Kanrokoti/強2階探索表記
- 解析対象は **rev 76153（2026-10-04 版）** です。
  https://googology.fandom.com/ja/wiki/ユーザーブログ:Kanrokoti/強2階探索表記?oldid=76153
  （2026-10-08 時点でこれが最新版です。古い版 76008 / 76057 も `?oldid=` で見られます。）

記法: w = ω, e0 = ε₀, e_x = ε_x, z0 = ζ₀。列は `(0,0,2,1)` のように書きます。

## 1. 定義（rev 76153 を文字どおりに読んだもの）

この節の添字はすべて 1 から数え、L = Length(S) とします。

```
S[n] = n                                   (L = 0)
     = (S_1..S_{L-1}) [f(n)]               (S_L = 0)
     = G ⌢ B^{f(n)} [f(n)]                 (それ以外)
f(n) = n + 1
G  = (S_k)_{k=1}^{fbp(br)}
B  = (S_k)_{k=fbp(br)+1}^{L-1} ⌢ (S_L − 1)
br = min({ i | 1 < i ≤ L ∧ ( suf(fbp(i)+1) ≤ suf(fbp(i−1)+1)
                              ∨ ∃j (p(i) < j ≤ fbp(i) ∧ S_j ≤ S_{p(i)}) ) } ∪ {L})
fbp(i) = mbp(p(i))
mbp(x) = L          (L ≤ x)
       = x          (S_x < S_L ∧ suf(mbp(x+1)+1) < suf(x+1))
       = mbp(x+1)   (それ以外)
p(i)  = sp^i(L)
sp(x) = max({ i ≥ 1 | i < x ∧ suf(i) < suf(x) } ∪ {1})
suf(k) = (S_k, …, S_L)        （k = L+1 なら空列）
```

列は左からの辞書式順序で比べます。真の接頭辞は元の列より小さいとします。
`./ssosn` がこの定義をそのまま実装しています（下の 3 節）。

**版ごとの違い（調べ済み）**

## 2. 現在の結果

### 2.1 確かめたもの（ε₀ まで）

(0,0) の後ろが 0 と 1 だけの列 (0,0)⌢Y では、次の式で値が決まります（`conj.py`）。

```
o((0,0)⌢Y) = 2 + v(Y)
v(Y) = 左から順に、各単位の値を足したもの
  単位 = かたまりの外にある 0          → 1
       = かたまり B                    → w^(1 + v(T(B)))
  かたまり = 0 を 1 個ずつはさんで 1 が並んだ最大の部分。0 が 2 個続くところで切れる
  T(B) = B の中の 1 の連続を、それぞれ 1 個ずつ短くした列
```

例:

| 列 | 値 |
|---|---|
| (0,0,1) | w |
| (0,0,1,0,1) | w^2 |
| (0,0,1,0,1,0,1) | w^3 |
| (0,0,1,1) | w^w |
| (0,0,1,1,0,1) | w^(w+1) |
| (0,0,1,1,0,1,1) | w^w^2 |
| (0,0,1,1,1) | w^w^w |
| (0,0,2) | e0 |

この式の確かさは、次のとおりです。
- この式から決まる「切れ目」は、本物の展開の切れ目と、標準形 2592 本で一致しました（`conj.py` の `rcut`）。
- この式を木の形にした展開（`tree.py`）は、本物の展開と、標準形 1372 本で一致しました。
- Lean（`lean/SSOS/Tree.lean`）では、木の上で次のことを証明済みです。
  - 展開の各項は元より小さい: `E_lt`
  - 展開の項の上限は元の値になる: `E_cof`
  - sup_n o((0,0,1^n)) = e0: `tower_lt_epsilon`, `tower_cof_epsilon`
  - 使った公理は propext, Classical.choice, Quot.sound だけです。
- **まだ証明していないこと**: 本物の sp / mbp / br で決まる切れ目が、木の切れ目と一致すること。これは数値で確かめただけです。

### 2.2 予想（e0 より上、仮定つきの計算）

| 列 | 値 |
|---|---|
| (0,0,2,0,0,1) | e0+w |
| (0,0,2,0,0,2) | e0·2 |
| (0,0,2,0,1) | w^(e0+1) |
| (0,0,2,0,1,2) | e1 |
| (0,0,2,0,1,2,0,1,2) | e2 |
| (0,0,2,0,2) | e_w |
| (0,0,2,0,2,0,2) | e_(w^w) |
| (0,0,2,1) | e_e0 |
| (0,0,2,1,0,1,2) | e_(e0+1) |
| (0,0,2,1,0,2) | e_e_e0 |
| (0,0,2,1,0,2,1), (0,0,2,1,1), (0,0,2,2), (0,0,3) | **不明**（計算が終わらない） |

使っている仮定は次の 2 つです。

```
仮定① (conj2.py): 0,1,2 を含む列にも 2.1 の式を使う。
   T(B) は「1 だけからなる連続」の先頭の 1 を 1 個消す。
   2 を含む連続はそのまま残す。
   (2) だけのかたまりの値は e0 とする。
   T(B) = B のかたまりを「自己参照ブロック」と呼ぶ。この値は①では決まらない。

仮定② (lower.py, 「下げる規則」): 自己参照ブロック u = 2 ⌢ f(x_1) ⌢ … ⌢ f(x_m)
   f(0) = (0,1,2), f(1) = (0,2), f(2) = (1)
   の値は e_ι とする。ここで ι = −2 + o((0,0,x_1,…,x_m))。
```

- 仮定②は、かたまり 53 個、標準形 91 本で、順序とも上限とも矛盾しませんでした。
- **しかし仮定②は正しくありません。**
  U⁴ = (0,0,2,1,0,2,0,1,2,1,0,1,2,0,2,1,0,2) で、②は e_e_e_e_e0 を出します。ところが実際の展開から出る値は e_e_e_(e0+1) です。
  長さ 21 以下のほかの U∞ の接頭辞では一致しました。
  このため、以前に出した「ζ₀ の候補」A6 = (0,0,2,1,0,2,0,1,2,1,0,1,2,0,2,1,0,2,0,1,2,0,2,1,0,2) は取り消しました。
- 「すき間がない」性質も、長さ 16 以下で確かめました。
  ```
  T < S（どちらも標準形）なら、ある n で T ≤ S[n]
  ```

## 3. スクリプト

すべて Python 3 で、標準ライブラリだけで動きます。**リポジトリの一番上のディレクトリで実行してください**（`ssosn` ファイルを相対パスで読み込むため）。

### 3.1 展開

```
./ssosn "0,0,2,1"          # (0,0,2,1)[1] を 1 段だけ展開する
./ssosn "0,0,2,1[2]"       # (0,0,2,1)[2]
./ssosn -v "0,0,2,1"       # p(i), すべての mbp(x), br, 切れ目, G, B も表示する
./ssosn --r76057 "..."     # rev 76057
./ssosn --old "..."        # rev 76008 で、切れ目を mbp(p(br)) にしたもの
./ssosn --fix "..."        # rev 76008 + 2026-09-27 に提案した修正
```

中身は `class Seq(S, mode)`（suf, sp, p, mbp, br, cut）と `step(S, n, mode)` です。

### 3.2 値を出す（今使っているもの）

| ファイル | 役割 |
|---|---|
| `ordinal.py` | Cantor / Veblen 標準形の順序数。`add`, `succ`, `lt`, `w`, `P(a,b)=φ(a,b)`, `show` |
| `evalord.py` | `sup`: 展開の項 o(S[1]), o(S[2]), o(S[3]) を見て上限を推測し、基本列で確かめる |
| `hyb.py` | 値を出す本体。`o(S)` の決め方は下に書きます。使い方: `python3 hyb.py 秒数 0,0,2,1 …` |
| `conj.py` | 2.1 の式（0/1 の列）。`units`, `T`, `v`, `o`, `rcut` |
| `conj2.py` | 仮定①（0/1/2 の列）。自己参照ブロックの値は `HOOK` に任せる |
| `lower.py` | 仮定②。`lower(u)`, `hook`, `fallback`（②を使わず再帰する） |
| `tree.py` | 0/1 の列を木の形にしたもの（Lean の `U` と同じ形） |
| `debug_prof.py` | 再帰の計測。呼び出しの回数、メモの大きさ、深さ、長さごとの数、一番深い呼び出しの列を出す |
| `debug_kind.py` | 各列がどの方法で値を決めたか、切れ目がどこかを数える |

`hyb.o(S)` は、上から順に次の方法を試します。

```
1. (0,0)⌢{0,1}*     → conj.o
2. conj2.o が値を出せる → その値
3. 最後が 0          → succ(o(S の最後を除いたもの))
4. 切れ目が「最後の 0,0」より右 → o(前半) + o(後半)
5. それ以外          → sup(o(S[1]), o(S[2]), o(S[3]))   （再帰）
```

仮定②を使うときは、次のようにします。

```
python3 -c "import hyb,lower,conj2; conj2.HOOK=lower.hook; print(hyb.show(hyb.o((0,0,2,1,0,2))))"
→ e_e_e0
```

## 4. Lean

```
cd lean
lake exe cache get     # Mathlib のビルド済みファイルを取ってくる
lake build             # SSOS/Tree.lean をチェックする
```

Lean と Mathlib はどちらも v4.33.1 です（`lean-toolchain`, `lakefile.toml`）。
`SSOS/Tree.lean` の内容は次のとおりです。
- `inductive U | z | b (List U)`: 単位。リストは最後の単位が先頭に来る順で持ちます。
- `val z = 1`, `val (b u) = ω^(1 + vs u)`, `vs (x :: l) = vs l + val x`
- `H`: 置き換え。`E (b u :: P) k = H u k ++ P`: 展開
- 定理: `H_head`, `H_spec`, `E_lt`, `E_cof`, `tower_lt_epsilon`, `tower_cof_epsilon`

## 5. いま詰まっていること

**e_e_e0 より先に進めません。**

計算が爆発するのは Python の再帰です。Lean では何も爆発していません。
`python3 debug_prof.py 0,0,2,1,0,2 20` で計測すると、次のようになります（仮定②なし）。

| 時間 | 調べた列の数 | 一番長い列 |
|---|---|---|
| 5 秒 | 2.1 万 | 209 |
| 10 秒 | 3.5 万 | 213 |
| 20 秒 | 6.3 万 | 259 |

- 再帰の深さは 68 段になります。
- 1 回の展開は長さ 76 でも 1 ms 未満なので、遅いのは呼ぶ回数のほうです。
- 理由: ε の領域では、ほとんどの列が `(0,0)⌢2…` という、0 が 2 個続くところのない 1 つのかたまりになります。例: `0021012020201201210120201…`
  - これは自己参照ブロックなので、値を `sup(o(S[1..3]))` の再帰で出すしかありません。
  - S[3] は B を 3 回コピーするので、少し長くなります。そして、それもまた自己参照ブロックです。
  - 同じ列はほとんど二度と出てこないので、メモが効きません。
- 無限ループではありません。S[n] < S なので、理屈の上ではいつか終わります。ただし手数が天文学的に多くなります。
- 仮定②を入れると (0,0,2,1,0,2) までは一瞬で出ます。しかし (0,0,2,1,0,2,1) では、②を入れても 120 秒以上かかって終わりません。

**必要なもの**: 自己参照ブロックの値を、再帰を使わずに出す正しい規則です。言い換えると、e0 より上での翻訳写像です。仮定②はその近似にすぎず、U⁴ で外れます。

## 6. 次にやること（候補）

- **A. 自己参照ブロックの正しい規則を見つける。**
  - 仮定②が外れる U⁴ のまわりで、実際の展開（`./ssosn -v`）を詳しく調べます。
  - 規則は、親（p(i)）や切れ目（mbp(p(br))）の構造から作るのがよさそうです。
  - 新しい規則は、少なくとも次の 3 つを満たす必要があります。
    1. 2.2 の確かめた値（長さ 13 以下は、再帰で確かめ済み）と一致する。
    2. U⁴ で e_e_e_(e0+1) を出す。
    3. 標準形で、辞書式の順序と値の順序が一致し、さらに o(S) = sup_n o(S[n]) が成り立つ。
  - 規則が見つかったら、(0,0,2,1,0,2,1), (0,0,2,1,1), (0,0,2,2), (0,0,3) の値を出して、ζ₀ / Γ₀ などへ進みます。
- **B. Lean で、本物の展開と木の展開の対応を証明する。**
  これで e0 までが完全に証明されます。証明すべきことは次のとおりです。
  ```
  (0,0)⌢{0,1}* の標準形で、sp / mbp / br から決まる切れ目 = 木の切れ目
  ```
- **C. 作者に、ψ との対応（意図している翻訳）を聞く。**

**注意**: 長時間の総当たり（数分以上かかる計算）は避けてください。時間制限をつけて、少しずつ試してください。
