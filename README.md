# ssosn — 強2階探索表記の順序数解析

Kanrokoti さんの「強2階探索表記」（strong second-order search sequence, SSOS）を順序数で解析しています。各列 S に順序数 o(S) を対応させて、小さい列から順に表を作るのが目的です。

- 定義: 巨大数研究 Wiki「ユーザーブログ:Kanrokoti/強2階探索表記」
  https://googology.fandom.com/ja/wiki/ユーザーブログ:Kanrokoti/強2階探索表記
- 解析対象は **rev 76153（2026-10-04 版）** です。
  https://googology.fandom.com/ja/wiki/ユーザーブログ:Kanrokoti/強2階探索表記?oldid=76153
  （古い版 76008 / 76057 も `?oldid=` で見られます。）
- 2026-10-13 に rev 76239 が出ました。名前の付け替えと、場合分けが 1 つ増えただけです。増えた場合分けは (0,0) で始まる列では使われないので、この README の結果はそのまま rev 76239 でも成り立ちます（`2026-10-17.md` の 0 節）。

記法: w = ω, e0 = ε₀, e_x = ε_x, z0 = ζ₀。列は `(0,0,2,1)` のように書きます。

## 1. 定義（rev 76153 を文字どおりに読んだもの）

この節の添字はすべて 1 から数え、L = Length(S) とします。

```
S[n] = n                                   (L = 0)
     = (S_1..S_{L-1}) [f(n)]               (S_L = 0)
     = G ⌢ B^{f(n)} [f(n)]                 (それ以外)
f(n) = n + 1
G  = (S_k)_{k=1}^{fbp(br)}
B  = (S_k)_{k=fbp(br)+1}^{L-1} ⌢ (S_L − 1)
br = min({ i | 1 < i ≤ L ∧ ( suf(fbp(i)+1) ≤ suf(fbp(i−1)+1)
                              ∨ ∃j (p(i) < j ≤ fbp(i) ∧ S_j ≤ S_{p(i)}) ) } ∪ {L})
fbp(i) = mbp(p(i))
mbp(x) = L          (L ≤ x)
       = x          (S_x < S_L ∧ suf(mbp(x+1)+1) < suf(x+1))
       = mbp(x+1)   (それ以外)
p(i)  = sp^i(L)
sp(x) = max({ i ≥ 1 | i < x ∧ suf(i) < suf(x) } ∪ {1})
suf(k) = (S_k, …, S_L)        （k = L+1 なら空列）
```

列は左からの辞書式順序で比べます。真の接頭辞は元の列より小さいとします。
`./ssosn` がこの定義をそのまま実装しています（下の 3 節）。

**版ごとの違い（調べ済み）**
- 2026-09-26 の rev 76008 を文字どおりに読むと、無限降下が起きます（例: a_k = (0,0,1,0^k,1), a_k[2] = a_{k+1} ⌢ 0^{k+1}）。

## 2. 現在の結果

### 2.1 確かめたもの（ε₀ まで）

(0,0) の後ろが 0 と 1 だけの列 (0,0)⌢Y では、次の式で値が決まります（`conj.py`）。

```
o((0,0)⌢Y) = 2 + v(Y)
v(Y) = 左から順に、各単位の値を足したもの
  単位 = かたまりの外にある 0          → 1
       = かたまり B                    → w^(1 + v(T(B)))
  かたまり = 0 を 1 個ずつはさんで 1 が並んだ最大の部分。0 が 2 個続くところで切れる
  T(B) = B の中の 1 の連続を、それぞれ 1 個ずつ短くした列
```

例:

| 列 | 値 |
|---|---|
| (0,0,1) | w |
| (0,0,1,0,1) | w^2 |
| (0,0,1,0,1,0,1) | w^3 |
| (0,0,1,1) | w^w |
| (0,0,1,1,0,1) | w^(w+1) |
| (0,0,1,1,0,1,1) | w^w^2 |
| (0,0,1,1,1) | w^w^w |
| (0,0,2) | e0 |

この式の確かさは、次のとおりです。
- この式から決まる「切れ目」は、本物の展開の切れ目と、標準形 2592 本で一致しました（`conj.py` の `rcut`）。
- この式を木の形にした展開（`tree.py`）は、本物の展開と、標準形 1372 本で一致しました。
- Lean（`lean/SSOS/Tree.lean`）では、木の上で次のことを証明済みです。
  - 展開の各項は元より小さい: `E_lt`
  - 展開の項の上限は元の値になる: `E_cof`
  - sup_n o((0,0,1^n)) = e0: `tower_lt_epsilon`, `tower_cof_epsilon`
  - 使った公理は propext, Classical.choice, Quot.sound だけです。
- **まだ証明していないこと**: 本物の sp / mbp / br で決まる切れ目が、木の切れ目と一致すること。これは数値で確かめただけです。

#### e_e0 より上の値の出し方（2026-10-16〜18）

(0,0,2,1) = e_e0 より上の値は、仮定②を使わずに出しました。詳しくは `2026-10-16.md` と `2026-10-17.md` にあります。

**部品**: (0,0,2,1) の後ろを、次の部品の並びとして読みます。

```
A_k = (0,1,2)⌢(0,2)^k      W = A0⌢1 = (0,1,2,1)      E = A1⌢1 = (0,1,2,0,2,1)      D = (0,2)
```

**展開の形の 3 つの規則**（本物の展開を部品の並びに直して読んだもの。`work/tokfs.py`）

```
L_E:  X⌢A_k⌢1 [n] = X⌢A_(k+n−1)⌢0
L_W:  X⌢Z⌢W [n]   = X⌢Z^n⌢A0⌢0          Z = 最後の単位（最後の部品と、その後ろの W）
L_A:  R⌢T⌢A_k [n] = R⌢T⌢A_(k−1)⌢(C⌢T⌢A_(k−1))^(n−1)⌢(0,1)      （k ≥ 1）
      R は、最後の A_d W^m（d < k, m > 0）までの部分。T はその後ろ。C = W^m。
      そういう単位がなければ、R = 先頭の W^j、C = W^(j+1)。
```

- 部品 9 個までの標準形 17828 本で、n = 1..5 の外れは 0 でした（`2026-10-17.md` の 15 節）。
- A0 で終わる列（+1）は、この 3 つの規則の対象外です。
- **2026-10-18: 展開の形は Lean で証明しました**（4 節、`2026-10-17.md` の 23 節）。
  - L_E（X⌢E）と L_W（Z = A_(k+1)・E・A0、W だけの場合）は、すべての n とすべての X で成り立ちます。X⌢A0 [n] = X⌢(0,1)⌢1^n も同じです。
  - L_A は、T についての 2 つの条件のもとで成り立ちます（`law_A_tok`）。T の A_e は e ≥ K で、T は W で始まらないこと。T の中の各 W・E の後ろの部分 T' について T'⌢A_K ≤ W^m⌢T⌢A_K であること（R の単位の (2,1) から始まるかたまりが、T の中の後のかたまり以上）。T が空なら条件なしです。標準形 5553 本はすべてこの条件を満たしました。
  - 値の読み方（下）は証明していません。

**値の読み方**

```
A0 = +1、 A_k = 深さ k で +1
W  = 直前の単位 Z の働きを ω 回くり返して上限を取る:  ι ↦ sup_n f_Z^n(ι)
     例: A0 W = +w、 A0 W W = +w^2、 A1 W = 指数に +w、 A1 W W = 指数に +w^2
E  = A_n の上限（その深さで次の ε 数）
```

- この読み方で値を出す道具が `work/token_value.py` と `work/token_tree.py` です（rule6・仮定②・展開のくり返しを使わない）。
- 値の確かめ:
  - lift（2026-10-16）の 5350 本と全部一致しました。
  - 標準形 106968 本で、展開の項 n = 1..5 がどれも元の列より小さく、n とともに大きくなりました。隣どうしの順序の矛盾も 0 でした。
- (2,1)W^j の添字 e_(w^j) と、(0,0,2,1,0,2) の値は、道具に書き込んであります。展開の項の上限がその値になることは、確かめてあります（(2,1)W = e_e_w から順に積み上がる形）。
- **一般に成り立つことは、まだ証明していません。** 有限個の列で確かめただけです。

**古い規則の間違い**: 前に使っていた `work/rule6.py` は、W W を「もう一度 +w」と読んでいました。
そのため (0,0,2,1,0,1,2,1,0,1,2,0,2,…) のあたりで値が小さすぎ、順序が壊れていました。
作り直した 977 本の表では、違いはこのあたりの 155 本だけでした（`2026-10-17.md` の 11〜15 節）。

使っている仮定は次の 2 つです。

```
仮定① (conj2.py): 0,1,2 を含む列にも 2.1 の式を使う。
   T(B) は「1 だけからなる連続」の先頭の 1 を 1 個消す。
   2 を含む連続はそのまま残す。
   (2) だけのかたまりの値は e0 とする。
   T(B) = B のかたまりを「自己参照ブロック」と呼ぶ。この値は①では決まらない。

仮定② (lower.py, 「下げる規則」): 自己参照ブロック u = 2 ⌢ f(x_1) ⌢ … ⌢ f(x_m)
   f(0) = (0,1,2), f(1) = (0,2), f(2) = (1)
   の値は e_ι とする。ここで ι = −2 + o((0,0,x_1,…,x_m))。
```

- 仮定②は、かたまり 53 個、標準形 91 本で、順序とも上限とも矛盾しませんでした。
- **しかし仮定②は正しくありません。**
  U⁴ = (0,0,2,1,0,2,0,1,2,1,0,1,2,0,2,1,0,2) で、②は e_e_e_e_e0 を出します。ところが実際の展開から出る値は e_e_e_(e0+1) です。
  （この「実際の値」は 2026-10-05 の計算で、古い規則に頼っていた可能性があります。見直していません。）
  ②は (0,0,2,1,0,1,2,1,0,1,2,1) や (0,0,2,1,0,2) でも、上の表の値と食い違います。
  長さ 21 以下のほかの U∞ の接頭辞では一致しました。
  このため、以前に出した「ζ₀ の候補」A6 = (0,0,2,1,0,2,0,1,2,1,0,1,2,0,2,1,0,2,0,1,2,0,2,1,0,2) は取り消しました。
- 「すき間がない」性質も、長さ 16 以下で確かめました。
  ```
  T < S（どちらも標準形）なら、ある n で T ≤ S[n]
  ```

## 3. スクリプト

すべて Python 3 で、標準ライブラリだけで動きます。**リポジトリの一番上のディレクトリで実行してください**（`ssosn` ファイルを相対パスで読み込むため）。

### 3.1 展開

```
./ssosn "0,0,2,1"          # (0,0,2,1)[1] を 1 段だけ展開する
./ssosn "0,0,2,1[2]"       # (0,0,2,1)[2]
./ssosn -v "0,0,2,1"       # p(i), すべての mbp(x), br, 切れ目, G, B も表示する
./ssosn --r76057 "..."     # rev 76057
./ssosn --old "..."        # rev 76008 で、切れ目を mbp(p(br)) にしたもの
./ssosn --fix "..."        # rev 76008 + 2026-09-27 に提案した修正
```

中身は `class Seq(S, mode)`（suf, sp, p, mbp, br, cut）と `step(S, n, mode)` です。

### 3.2 値を出す（今使っているもの）

| ファイル | 役割 |
|---|---|
| `ordinal.py` | Cantor / Veblen 標準形の順序数。`add`, `succ`, `lt`, `w`, `P(a,b)=φ(a,b)`, `show` |
| `evalord.py` | `sup`: 展開の項 o(S[1]), o(S[2]), o(S[3]) を見て上限を推測し、基本列で確かめる |
| `hyb.py` | 値を出す本体。`o(S)` の決め方は下に書きます。使い方: `python3 hyb.py 秒数 0,0,2,1 …` |
| `conj.py` | 2.1 の式（0/1 の列）。`units`, `T`, `v`, `o`, `rcut` |
| `conj2.py` | 仮定①（0/1/2 の列）。自己参照ブロックの値は `HOOK` に任せる |
| `lower.py` | 仮定②。`lower(u)`, `hook`, `fallback`（②を使わず再帰する） |
| `tree.py` | 0/1 の列を木の形にしたもの（Lean の `U` と同じ形） |
| `debug_prof.py` | 再帰の計測。呼び出しの回数、メモの大きさ、深さ、長さごとの数、一番深い呼び出しの列を出す |
| `debug_kind.py` | 各列がどの方法で値を決めたか、切れ目がどこかを数える |

`hyb.o(S)` は、上から順に次の方法を試します。

```
1. (0,0)⌢{0,1}*     → conj.o
2. conj2.o が値を出せる → その値
3. 最後が 0          → succ(o(S の最後を除いたもの))
4. 切れ目が「最後の 0,0」より右 → o(前半) + o(後半)
5. それ以外          → sup(o(S[1]), o(S[2]), o(S[3]))   （再帰）
```

仮定②を使うときは、次のようにします。

```
python3 -c "import hyb,lower,conj2; conj2.HOOK=lower.hook; print(hyb.show(hyb.o((0,0,2,1,0,2))))"
→ e_e_e0
```

これは仮定②の値です。②を使わない計算では e_(e_(w^w)) と予想されます（2.2 の注）。

## 4. Lean

```
cd lean
lake exe cache get     # Mathlib のビルド済みファイルを取ってくる
leanman build          # 全モジュールをチェックする
```

Lean と Mathlib はどちらも v4.33.1 です（`lean-toolchain`, `lakefile.toml`）。
`SSOS/Tree.lean` の内容は次のとおりです。
- `inductive U | z | b (List U)`: 単位。リストは最後の単位が先頭に来る順で持ちます。
- `val z = 1`, `val (b u) = ω^(1 + vs u)`, `vs (x :: l) = vs l + val x`
- `H`: 置き換え。`E (b u :: P) k = H u k ++ P`: 展開
- 定理: `H_head`, `H_spec`, `E_lt`, `E_cof`, `tower_lt_epsilon`, `tower_cof_epsilon`

2026-10-15〜16 に、実際の規則との対応に向けて次を追加しました。

| ファイル | 内容 |
|---|---|
| `SSOS/Def.lean` | rev 76153 の `suf`, `sp`, `p`, `mbp`, `fbp`, `br`, `cut`, `fs`, `step`。添字は 1 始まり |
| `SSOS/Flat.lean` | 木から列への変換 `flat`, `encode` と、連結・塔の変換の証明 |
| `SSOS/Expansion.lean` | 木の切れ目 `parts`。木の展開が「前半 + 後半の k 回コピー」になる証明 |
| `SSOS/Bridge.lean` | 切れ目の一致 `CutCorrect` を条件とする対応定理 `fs_encode`。値の減少・共終性への接続 |

## 5. いま詰まっていること

**(0,0,2,1,0,2) = e_(e_(w^w)) より先の値が出せません。**

- P = (2,1,0,2) の上の列では、本物の展開の形はかなり読めています（`2026-10-17.md` の 16〜18 節）。
  - 先頭に D を含む列（部品 8 個まで）の標準形 12376 本のうち、W で終わる 3146 本で、展開の形が全部一致しました。
- しかし値の読み方は、外れを一つ直すと別の外れが出ます。
  - 例: S = (2,1) D W A0 W D W の本物の展開は S[n] = (2,1) D W A0 W D A1^(n−1) A0 0 です。最後の W がくり返すのは A1 です。
  - 「W の後の D」を「くり返しの段を 1 つ上げる」と読むと、S[2] の値が S の値を超えてしまいます（17 節）。
  - 直した読み方でも、S = (2,1) D W A1 で同じことが起きました（18 節）。
- 原因: 展開で 1 が消えるか残るかが、前の部品がどの深さを開いたかで変わります。いまは「展開の形を見て、値の読み方を推測し、外れたら直す」をくり返しているので、この先は進みにくいです。

**必要なもの**: 部品の働きを、定義の展開の規則（親 p(i)、悪い部分、切れ目）から直接導くことです。
